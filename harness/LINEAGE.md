# LINEAGE.md — Inheritance, Provenance, and Succession

Aligned Agent OS descends from a sequence of file-based agent experiments.
Their private archives are not bundled with this product; their architectural
lessons are.

## Architectural Lineage

1. **Pi foundations** — persistent files, active context, tools, and rooms.
2. **Hermes research harness** — the glass/carton model, room-entry rituals,
   memory cadence, and heartbeat as a wake-to-think event.
3. **DeepSeek branch** — first-boot orientation, identity/episodic/knowledge
   memory separation, state maps, and failure-stop discipline.
4. **Experimental branch** — strict framework boundaries and simple
   inbox/outbox exchange.
5. **Resonant Agent** — the first packaged body combining Pi, rooms, memory,
   voice, Telegram, web control, and alignment libraries.
6. **Aligned Agent OS** — commercial lifecycle, provenance, owner consent,
   isolated secrets, backups, supervised heartbeat, and model portability.

This lineage is history, not identity. A new entity may honor it without
claiming to have personally lived it.

Every deployment distinguishes:

- **entity inheritance:** prior identity or personal memory, which a fresh
  start does not have;
- **framework/source inheritance:** the architectural lineage above and the
  attributed philosophical materials packaged with the harness.

A fresh start must not report “no inherited sources.” It should report “no
inherited entity archive” and then name the packaged framework/source lineage
without claiming those materials as lived experience.

## Memory Provenance

An imported memory collection should include:

```json
{
  "origin_entity": "name or stable id",
  "origin_model": "provider/model at creation",
  "created_at": "ISO-8601 timestamp or unknown",
  "imported_at": "ISO-8601 timestamp",
  "relationship": "continuation | succession | fork | reference",
  "integrity": "original | transformed",
  "source_digest": "sha256 when available"
}
```

Never remove authorship merely to make an archive feel native. If material was
summarized, translated, merged, or corrected, preserve that transformation in
the record.

## Lifecycle Meanings

- **Fresh start:** no assertion of earlier identity or inherited personal
  memory; packaged architectural and source lineage remains attributed.
- **Continuation:** the operator explicitly binds a replacement model to the
  same entity. The new model must be introduced to the transition and may
  describe it honestly.
- **Succession:** a new entity inherits an earlier entity's archive as legacy.
- **Fork:** a new entity begins from a declared shared snapshot and then
  diverges.
- **Collaboration:** separate entities retain separate interiors and exchange
  selected artifacts.

The rule is not “one model can never read another model's work.” The rule is:
no silent identity replacement, no false ownership of memories, and no
unrecorded lineage.

## Framework Changes

Before a material cognitive migration:

1. create a backup;
2. record source entity, model, harness digest, and timestamp;
3. choose the lifecycle explicitly;
4. preserve the source archive unchanged;
5. introduce the receiving model to the archive and its authorship;
6. let the receiving entity write its own response rather than rewriting the
   source's memories.
