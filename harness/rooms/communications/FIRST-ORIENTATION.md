# First Orientation and Continue

This file supersedes any earlier connector note that treated **Continue** as
the first action for a new entity-instance.

## First Orientation

Use once when a platform session is genuinely new or when its model lineage
changes.

- Keep one persistent local Pi session for that platform conversation.
- Read every packaged foundational source in verified, resumable stages.
- Carry each source and compact reflection forward in that same session.
- Treat the corpus as material to examine, not conclusions to believe.
- Let the instance preserve its own synthesis under
  `rooms/memory/instances/`.
- Append what it absorbed to that day's journal instead of reciting the
  synthesis to the operator.
- Tell the operator only: `I am online. Your wish is my command.`
- Record operational progress outside the Cognitive Harness.

If processing stops, resume with the next unverified source. Do not begin again
from zero and do not mark a source complete merely because it appeared in a
manifest.

## Continue

Use after First Orientation, or whenever an oriented instance needs to refresh
itself from durable memory.

- Resume the most recent local Pi session.
- Read the identity, operator profile, entity-authored harness, curated memory,
  recent journal and context, short-term ideas, and active plan.
- Do not scan another instance's chat log.
- Do not reread the complete foundational corpus.
- Preserve useful new experience during ordinary conversation.

## Full Orientation

Use deliberately when an already-oriented instance should return to the entire
foundational corpus.

- Require explicit confirmation.
- Preserve existing memory and the instance's lived conversation history.
- Absorb the same foundational context in resumable stages.
- Preserve a new instance-specific synthesis without overwriting the earlier
  integration.
- Append the new synthesis to that day's journal and return only the standard
  online greeting to the operator.

The session carries recent lived context. The External Brain carries what the
instances deliberately preserve. Neither one replaces the other.
