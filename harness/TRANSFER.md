# TRANSFER.md — Model and Entity Transitions

Never perform a silent model swap. Back up the runtime and choose a lifecycle.

## Fresh Start

Create a new entity and clean personal memory. It may receive shared knowledge
libraries but no implied lived history.

## Continuation

Use only when the operator explicitly chooses to preserve one entity across a
model change. Record both model bindings, transition time, reason, and harness
digest. Introduce the new model to the discontinuity honestly.

## Succession

Create a new entity. Import the prior entity's archive as inherited testimony.
The successor may learn from it without claiming authorship or experience.

## Fork

Create a new entity from a declared snapshot. Record common ancestry and the
fork point. Future memories diverge.

## Collaboration

Keep separate identities and private interiors. Exchange only designated
artifacts through explicit inbox/outbox or mesh channels.

## Transition Procedure

1. Create and verify a backup.
2. Record source entity, model, harness digest, and memory digest.
3. Choose the lifecycle explicitly.
4. Preserve the source archive unchanged.
5. Initialize the receiving entity and lineage record.
6. Import only the material allowed by that lifecycle.
7. Run first-boot orientation.
8. Verify the receiving entity describes the transition accurately.

Identity, episodic memory, knowledge, and operational configuration are
different layers. Move each deliberately.
